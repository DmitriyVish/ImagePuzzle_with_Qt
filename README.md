# ImagePuzzle 1.0

Приложение Qt Widgets на C++17: загрузите изображение, задайте число частей и соберите пазл мышью или пальцем.

Выберите музейную фотографию в начале списка и нажмите «Выбрать» или откройте свой файл.
Быстрые кнопки предлагают 4 / 8 / 12 / 16 / 20 частей; поле числа позволяет выбрать любое целое от 4 до 20.
В компактном окне готовые варианты скрыты, точное поле остаётся доступным.
«Меньше анимации» отключает появления заголовков, анимацию закрепления и свечение швов;
настройка сохраняется между запусками и сразу завершает уже начатые эффекты.
Игровые фрагменты перемещаются сразу вслед за указателем, без анимационного запаздывания.

## Использование

1. Нажмите «Своя фотография…» или выберите встроенную фотографию в списке и нажмите «Выбрать».
2. Укажите количество фрагментов и нажмите «Начать собирать».
3. Переносите фрагменты из правого лотка на левое поле. При отпускании рядом с правильной позицией деталь закрепляется.
4. После закрепления всех деталей появляется исходное изображение и сообщение о победе.

«Повторить» сохраняет разбиение и заново перемешивает детали. «Разбить заново» создаёт новую случайную геометрию.
«К выбору» позволяет выбрать другое изображение; введённое количество сохраняется, пока допускается новой картинкой.
Кнопки действуют мышью, касанием и клавиатурой (Tab, Space). Перетаскивание детали выполняется мышью или одним пальцем.
Дополнительные пальцы не перехватывают активную деталь. Отмена касания, потеря активности окна и изменение размера отменяют незавершённый перенос.

## Масштаб и обзор

Основное поле сборки занимает примерно две трети общей ширины, компактный лоток миниатюр — около трети.
Миниатюра при захвате увеличивается до размера детали на поле; точка под пальцем или мышью сохраняется.
При возвращении в лоток деталь снова уменьшается. Отмена жеста восстанавливает её прежние размер и положение.
Начальная раскладка уплотняется без перекрытий и не увеличивает высоту сцены сверх высоты фотографии.

- «+» и «−» или Ctrl+колесо мыши меняют масштаб.
- Перетаскивание пустого пространства перемещает обзор.
- Колесо без Ctrl и полосы прокрутки перемещают увеличенное поле.
- «Всё поле» вписывает поле и лоток; после победы — целое изображение.
- Изменение размера окна не меняет позиции деталей и прогресс. После ручного масштабирования масштаб сохраняется.

## Изображения и ограничения

Список форматов строится по установленным декодерам Qt. Проверяются JPEG, PNG, BMP, WebP, TIFF и PPM,
когда соответствующие плагины доступны; GIF читается как первое изображение, включая анимированные файлы.
Для многостраничных файлов используется первая страница. EXIF-ориентация применяется автоматически, прозрачность сохраняется.

Чтение выполняется в фоне. Рабочее изображение уменьшается с сохранением пропорций до 1600 пикселей по длинной стороне.
Предварительно распознанные изображения свыше 100 миллионов пикселей отклоняются; дополнительно действует ограничение памяти декодера Qt.
Количество частей — от 4 до 20, но фактический предел зависит от размера: сторона базовой ячейки не меньше 16 пикселей рабочего изображения.
Для очень маленького изображения начало игры недоступно. Ошибка чтения другого файла не удаляет ранее загруженное изображение.

Разбиение случайное, без вращения, с округлыми выступами и выемками. Соседи используют один общий контур
из кубических кривых Безье; на стыках кривых сохраняются совпадающие касательные. Внешний край фотографии ровный.
Ровно n фигурных деталей полностью покрывают изображение без перекрытий. Их изображения и выбор мышью/касанием
используют один контур, поэтому прозрачная выемка не захватывается как часть детали. После победы показывается
целый снимок без субпиксельных швов сглаживания.

При правильном отпускании деталь мягко доводится до точной позиции за 160 мс и на 220 мс подсвечивается её контур.
После последнего закрепления целое изображение плавно проявляется, а внутренние швы ненадолго светятся
тёплым золотистым ореолом и полностью гаснут за 480 мс. Внешняя рамка не подсвечивается.
Новая игра отменяет все отложенные эффекты предыдущего раунда.
Seed записывается в лог и воспроизводит геометрию в той же сборке приложения.
Тестовые изображения из `images/` встраиваются только в тестовые EXE и отсутствуют в ресурсах готового приложения.
Файлы в папке сохраняются для разработки; после добавления фикстуры достаточно пересобрать тесты.
В приложении остаются три музейные фотографии, шрифт и иконка; посетитель также может загрузить свой файл.
При `BUILD_TESTING=OFF` сборка приложения не зависит от папки `images/`.

## Архитектура

- `src/io/imageloader.*` — независимый загрузчик QImage, вызываемый через QtConcurrent.
- `src/core/puzzlegenerator.*` — разбиение с квотами и проверкой вместимости дочерних областей.
- `src/core/puzzlemodel.*` — геометрия, раскладка без начального наложения, позиции и закрепление деталей.
- `src/app/appcontroller.*` — состояния Configuring, Preparing, Playing, Completed.
- `src/app/gamecontroller.*` — подготовка, отмена, повтор, перемещения и завершение игры.
- `src/ui/` — экраны, предпросмотр и общая графическая сцена с адаптерами мыши/касания.
- `tests/unit/`, `tests/integration/`, `tests/ui/` — проверки логики, форматов, полного цикла и событий пользователя.

Модель — источник истины. Перенос до отпускания меняет только представление; контроллер принимает итоговую позицию.
Изображение разделяется через QImage implicit sharing, а не копируется целиком для каждой детали.
Документация и комментарии написаны по правилам `AGENTS.md`. Логи используют категории
`imagepuzzle.app`, `imagepuzzle.io`, `imagepuzzle.puzzle`, `imagepuzzle.ui` и `imagepuzzle.input`.
Диагностика начала/конца жестов включается правилом `QT_LOGGING_RULES=imagepuzzle.input.debug=true`.
Сообщения каждого движения или кадра не пишутся.

## Сборка

Требуются Qt 6.8+ с Widgets, Concurrent и Test (для тестов), CMake 3.16+, Ninja и совместимый C++17-компилятор.
Проверено на Windows x64: Qt 6.10.1, MinGW 13.1.0, CMake 3.30.5.

В Qt Creator откройте корневой `CMakeLists.txt`, выберите Desktop Qt 6.10.1 MinGW 64-bit,
выполните конфигурирование и соберите цель `ImagePuzzle`. Прежний каталог Debug сохраняется.
`ImagePuzzleCore` и `ImagePuzzleUi` — внутренние статические библиотеки приложения и тестов.

Из PowerShell в корне проекта:

```powershell
$env:PATH = 'C:\Qt\Tools\CMake_64\bin;C:\Qt\Tools\mingw1310_64\bin;C:\Qt\6.10.1\mingw_64\bin;C:\mingw64\bin;' + $env:PATH
& 'C:\Qt\6.10.1\mingw_64\bin\qt-cmake.bat' -S . -B build/dev -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=C:/Qt/Tools/mingw1310_64/bin/g++.exe -DCMAKE_MAKE_PROGRAM=C:/mingw64/bin/ninja.exe
cmake --build build/dev --parallel 2
ctest --test-dir build/dev --output-on-failure --parallel 2
```

Тесты включены по умолчанию (`BUILD_TESTING=ON`); их можно отключить при конфигурировании.
Отчёты JUnit сохраняются в `build/.../tests/*.xml`.
Наборы CTest: `unit.puzzle`, `unit.appcontroller`, `integration.images`,
`integration.gamecontroller`, `ui.mainwindow`. Геометрия и полный цикл контроллера проверяются
для каждого количества деталей от 4 до 20. Проверки анимаций включают пиксели свечения,
снимок без швов, отключение движения, отмену и уничтожение сцены с активными таймерами.

После сборки всех тестовых целей в Debug и Release итоговый прогон с HTML, Markdown,
JSON и отдельными JUnit XML для каждого запуска можно повторить командой (Python 3.9+):

```powershell
python scripts/final-testing.py --output build/final-test-report --native-windows
```

Скрипт использует каталоги `build/Desktop_Qt_6_10_1_MinGW_64_bit-Debug` и `build/release`.
Он выполняет полный прогон обеих конфигураций, UI при 150%/200%, пять повторов UI при 100%.
Флаг `--native-windows` добавляет полный UI-прогон через обычный Windows-плагин Qt с показом тестовых окон.
В PATH должны быть Qt и CTest. Для нового прогона используйте новый каталог отчёта.
Служебные `initTestCase` и `cleanupTestCase` учитываются отдельно от предметных тестов.
UI-тесты используют offscreen и имитируют клавиатуру, мышь, реальные QTouchEvent, несколько пальцев,
отмену, выбор и отмену файлового диалога, ошибки файлов, победу, повтор, новый пазл, масштабирование и resize.
Касания адресуются через QWindow для корректного тестирования при повышенном DPR.
Системный Segoe UI подключается в Windows offscreen-тесте для достоверной геометрии текста.
Физический сенсорный экран нужно дополнительно проверить вручную: автоматические события не измеряют задержки оборудования и особенности драйвера.

## Windows-сборка

Значок приложения — зелёная деталь пазла Microsoft Fluent Emoji (MIT).
Он встроен в Qt-ресурсы для заголовка и панели задач и в Windows PE-ресурс `.exe` для Проводника и ярлыков.
ICO содержит девять размеров от 16 до 256 пикселей с прозрачностью; исходный SVG и лицензия находятся в `assets/icons/`.
При изменении ICO Windows может сохранять старый значок в кэше Проводника; новый файл сборки содержит актуальный ресурс.

```powershell
.\scripts\build-windows.ps1 -OutputDirectory 'C:\Temp\ImagePuzzle-Windows-x64'
```

Скрипт собирает Release, запускает тесты и `windeployqt`, добавляет runtime компилятора и русские переводы Qt.
Выходной каталог должен быть новым, чтобы не смешивать библиотеки разных сборок.
Готовую папку можно перенести на другой компьютер и запустить `ImagePuzzle.exe`.
Для технической проверки комплекта без показа окна:

```powershell
.\ImagePuzzle.exe --self-test --self-test-report self-test.json
```

Эта проверка читает все встроенные изображения и собирает 17-частные пазлы для игровых фотографий,
не требует Qt Test и возвращает код 0 при успехе.
